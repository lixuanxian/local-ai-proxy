# CLAUDE.md

## Project Overview

Local AI Proxy is a unified API gateway that routes chat requests to multiple AI providers through both OpenAI-compatible and Anthropic-compatible endpoints. It includes a React web dashboard for management, SQLite persistence

**Port:** 3199 (configurable via `PORT` env var)

## Architecture

### Provider System

Providers follow an adapter pattern with two base classes:
- **`BaseCLIProvider`** — spawns local CLI processes (`child_process`), buffers stdout
- **`BaseAPIProvider`** — makes HTTP requests, supports SSE streaming

Each provider defines:
- `modelPatterns` — regex array for auto-routing by model name
- `buildArgs()` / request construction
- Response/stream parsing

### Request Flow

1. Request arrives at `/v1/chat/completions` (OpenAI) or `/v1/messages` (Anthropic)
2. Messages array validated
3. Provider resolved: explicit `provider` param → model name pattern match → default
4. Provider's `chat()` or `chatStream()` called
5. Response formatted to match the request's API format
6. Logged to SQLite if logging enabled

### Database (SQLite with WAL mode)

Tables: `providers`, `settings`, `request_logs`, `apps`, `docker_configs`, `conversations`, `messages`, `skills`

Migrations run automatically on startup in `lib/db.js`.

### Chat System

The `/chat` page provides a conversational AI interface:
- **Conversations** — persistent chat threads with title, provider, model, and settings
- **Streaming** — SSE-based real-time response streaming via `ReadableStream` reader
- **Modes** — Plan (outline approach first) and Edit (direct implementation) toggle
- **Role/System Prompt** — per-conversation system prompt with preset roles (Code Assistant, Writer, Translator, etc.)
- **Model settings** — temperature and max_tokens configurable per conversation
- **Skills** — reusable prompt templates (Code Review, Explain, Translate, Summarize, Write Tests) prepended to messages
- **File upload** — images and files via multer, stored in `data/uploads/`, served at `/uploads/`
- **Markdown** — assistant messages rendered with `react-markdown` + `remark-gfm`
- **Auto-title** — first message content used as conversation title

Database: `conversations` (id, title, provider_id, model, system_prompt, temperature, max_tokens), `messages` (id, conversation_id, role, content, attachments), `skills` (id, name, prompt_template, enabled, sort_order)

## Key Conventions

- **No test framework** — the project has no unit/integration tests
- **Backend:** Plain Node.js + Express, no TypeScript, no transpilation
- **Frontend:** React 19 + Ant Design 6, Vite 7, ESLint 9
- **Styling:** Custom CSS design system + Ant Design ConfigProvider theme tokens (no CSS-in-JS, no Tailwind)
- **Database:** Synchronous `better-sqlite3` — no async/await needed for DB calls
- **Streaming:** SSE format, chunked via `res.write()` with `text/event-stream` content type
- **API keys** are masked (`***`) in management API responses
- **Request logging** truncates bodies to 10KB
- **Frontend builds** output to `public/` which is served as static files by Express
- **No TypeScript, no Prettier** — raw JS with ESLint for the frontend only
- **Error handling:** ErrorBoundary component wraps the app; pages show empty states and skeleton loaders
- **Code splitting:** Pages are lazy-loaded; initial bundle ~15KB, each page ~5-10KB
- **Token tracking:** Log stats include total input/output token counts
